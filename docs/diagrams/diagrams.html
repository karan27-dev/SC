03 — Prediction lifecycle

What happens on POST /api/predict

One request returns a score, a reason and a plan. The model regime is chosen automatically from the inputs, and every recommendation is re-scored by the same model before it reaches the teacher.

01 · INPUT
Feature payload
Partial JSON. Missing fields fall back to defaults.
02 · NORMALISE
Validate & coerce
Bools → yes/no, gender & subject aliases, unknown values → 422.
G1 and G2
provided?
03a · REGIME
Full model
33 inputs incl. period grades · AUC 0.97
03b · REGIME
Early-warning model
31 behavioural & background inputs · AUC 0.81
04 · SCORE
Classifier + regressor
P(fail) → risk tier
high ≥ 60% · medium ≥ 30%
grade 0–20 → band A–F
05 · EXPLAIN
Baseline substitution
Swap each feature for the population median/mode, measure Δ pass probability.
06 · PLAN
Counterfactual planner
Re-score actionable changes only; greedily stack the ones that still help.
07 · PERSIST
Prediction row
Saved with mode, scores & payload → student timeline.
